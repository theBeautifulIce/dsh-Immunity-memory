# 开发说明

写给接手这个仓库的人（或下一次会话的 agent）。目标是：打开任意一个源文件之前，
先知道它为什么存在、边界在哪、改哪里安全。

## 1. 形态与三层职责

这是一个 **DSH 插件包**，不是独立应用。运行期由三个进程/层组成：

| 层 | 代码 | 职责 | 失效时 |
| --- | --- | --- | --- |
| Node 控制层 | `index.js`、`lib/*` | 插件入口 `apply(ctx)`、工具、提示词注入、设置页接口、维护与备份编排 | 插件不可用 |
| Go 服务 | `go-service/` → `bin/win32-x64/memory-service.exe` | SQLite（WAL）+ FTS5 检索 + 向量余弦 + 图谱 BFS + 审计/备份/完整性 + 优雅退出 | 自动退回 Node 内置实现 |
| Rust 核心 | `native/memory-core/` → `packages/memory-plugin/native/win32-x64/memory-core.exe` | 批量余弦、重要性评分、去重/相似度 | 自动退回 JS 实现 |

边界是刻意的：

- 插件宿主入口与浏览器端模块**必须是 JS**（cordis 契约：`apply(ctx)` 与 `window.__ModuleLoader__`），
  但检索与持久化没有这个限制。
- Node 自带的 `node:sqlite` **没有 FTS5**（`no such module: fts5`），Go 的 `modernc.org/sqlite`
  是纯 Go、免 cgo、FTS5 开箱可用，所以 SQLite 的所有权在 Go 服务。
- 设计文档里的 gRPC 用**回环 HTTP/JSON + 随机 token** 替代：Node 侧零依赖、安装不联网、
  不需要 `.proto` 编译链；语义等价（请求/响应 + 错误码 + 健康检查）。

## 2. 生命周期

1. `index.js` 的 `apply(ctx)` 是 async：先 `await createStorage(...)`，再 `await createEngine(...)`，
   引擎构造末尾 `await api.reload()`。
2. `createStorage` 按 `storage.engine` 选择：`auto`（默认）→ 尝试 Go 服务 → 失败则 Node SQLite
   → 再失败则 JSON。`go` 强制 Go，`sqlite`/`json` 强制回退层。回退会写 warning 日志，设置页
   「维护」里也能看到当前引擎。
3. `createGoStore` spawn `memory-service.exe`，参数 `-db <path> -token <random>`；
   服务在 stdout 打**一行**握手 `{"port":N,"pid":P,"version":"0.1.0","db":"..."}` 后开始服务，
   只监听 `127.0.0.1`。Node 用这个端口 + `x-memory-token` 调所有接口。
4. **服务二进制先暂存到数据目录再启动**：`stageServiceBinary()` 把二进制复制到
   `<库目录>/service/<platform>/memory-service.exe`，stamp 文件记录 `大小:mtime`，复制后校验
   sha256，`rename` 原子替换（旧进程占用时保留旧副本）。这样做有两个原因：开发态 `link:` 安装
   时二进制在 workspace 内，宿主沙箱会把它限制成只能写 workspace，Go 子进程因此打不开
   `~/.dsh` 下的库（`unable to open database file`）；正式安装也可能落在只读目录或 asar 里。
   设置 `DSH_MEMORY_SERVICE` 时跳过暂存，直接用指定路径。
5. Rust 核心在 `apply()` 里预热一次（`native.warmup()`），设置页能立刻显示真实状态；之后
   按需重启。协议是 JSON lines over stdio，握手命令 `ping` 返回
   `{"version":"0.1.0","protocol":1}`。
6. 卸载/重载时 `engine.close()` → `store.close()`：先 `POST /shutdown`，再 `kill`，
   **并等待子进程真正退出**（Windows 上 SQLite 文件句柄要等进程结束才释放，否则后续清理会 EBUSY）。

覆盖二进制的环境变量：`DSH_MEMORY_SERVICE`（Go 服务路径）、`DSH_MEMORY_CORE`（Rust 核心路径）。

## 3. 数据模型

库文件默认 `~/.dsh/storages/dsh-memory-plugin/memory.sqlite3`（`DSH_HOME` 可覆盖）。
Go 侧 `SchemaVersion = 4`，迁移顺序：

| 版本 | 内容 |
| --- | --- |
| v1 | `memories` / `events` / `assets` / `relationships` / `changelog` / `config` + 设计 §7.2 的索引 |
| v2 | `items_fts`（FTS5，中文按单字 + 二元组预切） |
| v3 | `memory_vectors`（384 维 float32 BLOB） |
| v4 | `items_meta`（layer/type/status/notebook/tags，供检索过滤） |

Go 用**独立**的 `service_migrations` 表记录 `version / description / applied_at`（迁移在一个事务里逐版本执行）。
不共用 Node 回退层的 `schema_migrations`，因为两边版本号含义不同（Node 的 v2 是向量表，Go 的 v2 是
FTS5）；共用会让 Go 误以为全文索引已经建好而跳过建表。独立后 Go 对任何旧库都从 0 跑一遍幂等迁移。
`Open()` 在迁移之后还会调用 `backfillIndexes()`：旧库（Node 回退层没有 FTS5）的 `items_fts` /
`memory_vectors` 行数对不上时，用 `Load()` + `UpsertItems()` 一次性补齐旧条目的索引。

条目（memory/note）关键字段：

| 字段 | 说明 |
| --- | --- |
| `id` | `mem_` + 12 位随机串 |
| `type` | `memory` / `note` |
| `layer` | `L0`…`L7` |
| `notebook` | `memory` / `daily` / `asset`（落到 memories / events / assets） |
| `title` / `content` / `tags[]` | 正文 |
| `importance` | 1–10（库里换算成 0–1 的 `importance_score`） |
| `status` | `active` / `archived` / `expired` / `conflicted` |
| `pinned` | 置顶，跳过自动维护 |
| `ttlDays` / `expiresAt` | 保鲜期（库里存 `freshness_period` 秒） |
| `accessCount` / `lastAccessAt` | 检索命中累加 |
| `version` / `conflicts[]` / `duplicateOf` | 修订与冲突信息 |
| `source` | `{ kind: 'user'|'agent'|'import', sessionId, workspace }` |

同步策略（`lib/go-store.js`）：Node 侧以条目**行签名**（`itemSignature`）做差异，每批 200 条
`/items/upsert` 或 `/items/delete`；`config` 存 `settings` / `meta` / `createdAt`；审计前缀没变就
只追加增量，否则整表替换（`compact` 之后会触发）。因此每次写操作不是整库重写。

JSON 单文件（`store.json`）只作为显式引擎与最后兜底保留；早期数据在首次启动时自动迁移进 SQLite。

## 4. 检索

统一入口 `engine.searchItems(options)`（async），三种出口：

1. `breakdown: 'listing'`：空查询，按重要度/时间列一批，不走索引。
2. `breakdown: 'go'`：Go 服务可用。FTS5 + 向量 + 图谱 + 融合全在 Go 内完成，Node 只做装饰与访问计数。
3. `breakdown: 'hybrid'`：Go 不可用时的 Node 回退（`lib/search.js`，内存倒排 BM25 + 余弦 + BFS）。

Go 侧流程（`go-service/internal/search/search.go`）：

- **全文**：`bm25(items_fts)` 排序并归一化；查询先经 `text.Tokenize`（中文单字 + 二元组，英文按词）。
- **语义**：读 `memory_vectors` 的 float32 BLOB 与查询向量算余弦；候选集来自全文命中，避免全表扫描。
- **图谱**：以前 N 个全文命中为种子（`graphSeeds`，默认 5）做 BFS，深度 `graphDepth`（默认 2），
  跳过边权低于 `graphMinWeight`（默认 0.5）的边，相关度按 `current * edgeWeight * 0.8` 衰减。
- **融合**：`fulltext / semantic / graph` 三路权重归一化后加权求和（默认 0.4 / 0.4 / 0.2；
  全零时退化为均分）。返回每条命中的 `breakdown{fulltext,semantic,graph,final}`。
- **过滤**：layer / type / notebook / tags（`items_meta`）、status（`usable`=active+conflicted）。

其它细节：

- Node 回退层有 LRU 结果缓存（`retrieval.cacheSize`，默认 256）；Go 路径不做二次缓存，避免两处失效。
- 命中会累加 `accessCount` / `lastAccessAt`；落盘用 1500ms 防抖（`scheduleAccessPersist`），
  `reload` / 关闭前 `flushAccess`。这是把混合检索从 21ms 降到 3–7ms 的关键，别改回"每次检索写库"。
- `retrieval.semantic=false` 时 Go 跳过向量路，`graph=false` 时跳过图谱路；两者都关就只剩 FTS5。

## 5. 引擎行为（`lib/engine.js`）

- **写入门槛**：`enabled` 关闭 → 拒绝；层被关掉 → 拒绝；不可变层（L0/L1/L3）编辑 → 拒绝
  （除非 `write.allowImmutableEdit`）；正文短于 `write.minContentLength` → 拒绝。
- **去重**：新条目与已有条目 jaccard 相似度 ≥ `write.dedupeThreshold` 时仍写入，
  返回 `duplicateOf`，维护任务 `dedupe` 给出提示。
- **冲突**：写 L2 且与同层条目相似度过高（默认 0.82）→ 置 `conflicted`，并在 `relationships`
  写一条 `conflict` 边（图谱检索与界面「关系」都用它）。
- **维护任务**（`runMaintenance`，可单跑也可按 `maintenance.intervalHours` 自动跑）：
  `limits`（超过 `maintenance.maxItems` 时按重要度裁掉最低的）、`cleanup`（过期）、
  `rotate`（低重要度/过期的轮转记忆归档，阈值 `rotateMinImportance`）、`archive`（长期未访问）、
  `dedupe`、`reflect`（高频访问条目提升重要度并给合并建议）、`compact`（压缩审计日志）。
- **备份**：Go 侧 `POST /backup` 生成 `backups/backup_<时间戳>_<tag>.sqlite3`，保留最近 10 份；
  恢复前先校验 SQLite 完整性。Node SQLite 回退层按 `storage.backupKeep` 轮转 `memory.sqlite3.bak-N`。
  自动备份由 `storage.autoBackup` / `autoBackupHours`（默认开、24h）驱动。
- 所有会落盘的方法都是 async；调用方（api/tools/测试）必须 await。

## 7. 接口（`lib/api.js`）

`POST /dsh-memory-plugin/api/v2`，body `{ "method": "items.list", "params": { ... } }`，返回
`{ "ok": true, "value": ... }` 或 `{ "ok": false, "error": { "code", "message" } }`。

方法：`bootstrap`、`status`、`health`、`items.list`、`items.search`、`items.get`、`items.create`、
`items.update`、`items.delete`、`items.bulk`、`settings.get`、`settings.save`、`settings.reset`、
`maintenance.run`、`prompt.preview`、`audit.list`、`data.export`、`data.import`、`search.stats`、
`indexes.rebuild`、`backups.list`、`backups.create`、`backups.restore`、`graph.neighbors`。

`health` 会真的去 `store.verify()` 与 `store.stats()`，返回存储引擎、Go 服务 `pid/port/version`、
表行数、完整性结论、原生核心版本——设置页「维护」里显示的就是它。

安全：每个请求校验 Host（回环或 DSH trustedHosts）、`sec-fetch-site`、`Origin`，跨站直接 403；
body 上限 2MB。路由挂在新前缀上（不复用旧前缀的子孙路径），重装时通过 holder 取当前引擎，
避免闭包住上一代引擎导致读到旧数据。

## 8. 客户端（`client.js`）

- 注册三处：`sidebar.panellist`（`id='memory'`，order 20，侧边栏图标）+ `main`（`key='memory'`，整页）
  + `settings.section`（`id='memory-plugin'`，order 60，设置页入口）；前两者 id/key 必须同名，
  宿主才会把图标点击切到我们的主面板。
- 整页容器自己滚动：`height:100%; minHeight:0; overflowY:auto`（`main` 槽位外层是 `overflow:hidden`）。
- 取数：`bootstrap` 一次拿回设置、表单 schema、统计、分层、记事本、审计、存储信息。
- 结构：统计徽章 + 四个 tab（记忆 / 记事本 / 设置 / 维护）。
- 维护面板：七个任务 + 全部运行、立即备份、重建索引、存储卡片（引擎/服务版本/表行数/原生核心）。
- 样式整段 CSS 注入，颜色只用 `--dsw-alias-*` 变量并带兜底色；`.mp-page` 作用域下列表随视口加高。

## 9. 构建

```pwsh
node scripts/build-native.mjs   # Rust → native/<platform-arch>/memory-core.exe
node scripts/build-go.mjs       # Go   → bin/<platform-arch>/memory-service.exe
node scripts/build-go.mjs --check   # 只探活已有二进制
```

- Rust：在仓库根目录的 `native/memory-core` 跑 `cargo build --release`，产物复制到
  `packages/memory-plugin/native/<platform-arch>/` 后跑 `ping` 自检并打印 sha256。无第三方运行时依赖。
- Go：`go build -trimpath -ldflags "-s -w"`；首次构建需要网络拉 `modernc.org/sqlite`
  （本机 GOPROXY 用 `goproxy.cn`）。构建脚本用 `.tmp/build-check-*` 起服务做健康自检并清理。
- 二进制已提交在仓库里，普通安装不需要构建链；换平台时按上面的命令重新产出对应目录。

## 10. 测试与基准

```pwsh
node scripts/check.mjs
```

| 套件 | 覆盖 |
| --- | --- |
| `tests/engine.test.mjs` | 设置归一化、去重、冲突、检索、维护、导出导入 |
| `tests/engine-go.test.mjs` | 同一套引擎行为跑在真实 Go 服务上（落库、检索、冲突边、备份） |
| `tests/tools.test.mjs` | 6 个工具的 schema 与真实执行 |
| `tests/search.test.mjs` | Node 回退检索：BM25、余弦、图谱、融合、缓存 |
| `tests/sqlite.test.mjs` | Node 回退存储：建表、分表映射、迁移、增量写、删除、重开 |
| `tests/native.test.mjs` | Rust 核心协议与 JS 兜底 |
| `tests/go-service.test.mjs` | Go 服务端到端：FTS5 中文、语义、BFS、过滤、配置、备份、审计、鉴权 |
| `tests/api.test.mjs` | 真实 http server 跑接口、错误码、Host 伪造拦截 |
| `tests/client.render.mjs` | 用真实 react-dom/server 渲染设置页与各面板 |

基准（脚本 `scripts/benchmark.mjs`，会 spawn 真实 Go 服务与 Rust 核心）：

```pwsh
node scripts/benchmark.mjs --items 2000 --queries 100 --graph 50 --out docs/性能报告.md
```

本机参考值：批量导入 ~1830 条/秒、单条写入 12.9ms、混合检索 6.9ms（p95 9.4）、
关语义检索 4.5ms、图谱 BFS 0.58ms、Rust 余弦 ~23600 对/秒、重要性 ~42 万条/秒、去重 ~1.6 万条/秒。
数字随机器变化；比较不同版本时只看同一台机器上的相对值。

两个容易踩的测量坑：

- 检索耗时里不要夹 `replaceSettings`（一次设置落盘 = HTTP + SQLite 事务，~40ms），
  语义开关要在计时循环外切一次。
- 访问计数已防抖；如果把 `scheduleAccessPersist` 改回同步写库，混合检索会退回 20ms 级。

## 11. 发布 / 更新

1. 改完先跑 `node scripts/check.mjs`（含 Go/Rust 套件；二进制缺失时会跳过并警告）。
2. `git add -A && git commit -m "feat: …"`。
3. 在 DSH 里重新 `plugin_manager install_bundle`（同一路径）。替换已安装版本需要重启 DSH 才换代码；
   新装则热生效。
4. 刷新/重开 Web 页面验证：左侧栏出现「记忆」图标，点开是整页列表；设置页入口仍能打开；
   列表能读、能写、设置能存、维护能跑、存储卡片显示 Go 服务与 pid/port。
   （client.js 改动由宿主的客户端模块加载器热更新；改完用 `cordis_inspect_query` 的
   `Slots.listSubTree` 确认 `sidebar.panellist` 里有 id `memory`、`main` 里有 key `memory`。）

## 12. 已知限制

- 语义向量是 **384 维哈希向量**（`lib/embeddings.js`），不是神经 embedding：无需模型、离线可用、
  可复现，但同义改写召回弱于真实向量模型。接真实模型只需替换 `embeddings.js` 的向量来源
  （表结构与 384 维约定可调）。
- 设计文档的 gRPC 用本地 HTTP/JSON 替代（理由见 §1）；若将来要跨机部署，再补 gRPC 不影响存储层。
- Node 回退层没有 FTS5，检索是内存倒排；只作为二进制缺失时的兜底，性能与中文召回都弱于 Go 路径。
- 去重是 O(n²) 的 jaccard，2000 条约 120ms；十万级应改成 LSH/分桶。
- 仓库只提交了 `win32-x64` 的二进制；其他平台需本地构建对应目录。
- 同一份 SQLite 被多个进程同时写时靠 `busy_timeout(5000)` + WAL，不保证高并发写吞吐。
